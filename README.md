# GoFetchX

GoFetchX 是一个基于 Go 和 Fyne 的 Windows 图形化下载器，支持多线程分块下载、断点续传、基础限速和下载状态持久化。

## 功能

- 多并发分块下载
- 断点续传
- 下载进度、速度、剩余时间显示
- 下载状态持久化
- 中文响应头文件名解析与同名文件自动避让
- 可配置下载目录
- 基础带宽探测与限速比例控制

## 项目结构

```text
GoFetchX/
├─ cmd/gofetchx/                # 程序入口
├─ internal/downloader/         # 下载核心逻辑
├─ internal/gui/                # Fyne 图形界面
├─ go.mod

└─ README.md
```

## 运行环境

- Go `1.24.3`
- Windows `amd64`
- Fyne `v2.7.3`
- 可用的 MinGW-w64 工具链

本项目在 Windows 下构建 GUI 程序时依赖 `cgo`。如果本机存在多套 `gcc/as/ld`，建议只保留一套参与构建，避免混用导致编译失败。

## 编译

项目入口：

```powershell
.\cmd\gofetchx
```

推荐在 PowerShell 中先指定 Go 与 MinGW-w64 工具链，再执行构建：

```powershell
go clean -cache
go build -a -ldflags="-H windowsgui -s -w" -o GoFetchX.exe .\cmd\gofetchx
```

## 下载状态与验证

暂停是异步操作：任务先进入 `pausing`（暂停中），等待下载协程和正在进行的周期保存退出、最终状态保存完成后，才对界面发布 `paused`（已暂停）。此时可以继续下载。取消同样先进入 `cancelling`，后台退出后清理状态文件并进入 `cancelled`。

同一个下载器在会话尚未结束时不能重复启动。下载中的重复 `Start()` 返回 `ErrDownloadRunning`，暂停或取消期间返回 `ErrDownloadStopping`。界面通过通知和状态快照更新按钮，暂停中不显示继续按钮。

分块下载会核对 `Content-Range`、文件总大小、已声明的响应长度和实际数据长度，限制写入范围，并在响应正常结束后才提交最后一段数据和标记分块完成。短响应保留已写入进度供重试；错误范围或超长响应直接报告错误。

服务端提供 `Content-MD5` 时，下载结束后将其按 Base64 解码为 16 字节摘要，与本地文件计算出的 MD5 比较。仅校验成功后才标记 `completed`；摘要不一致、响应头格式错误、校验时打开/读取文件失败都会进入 `error`，原因保存到 JSON 并在卡片“详情”中显示。校验失败的文件保留供排查，重试会重新下载所有分块，仍使用原文件名。普通分块错误则继续从已记录的进度重试。

JSON 的 `actual_hashes.md5` 继续保存易读的十六进制摘要，与服务端使用的 Base64 只是表示方式不同。没有 `Content-MD5` 时只检查分块完整性，不代表已验证文件哈希。`ETag` 不保证是 MD5，不作为文件摘要比较。

## 进度、界面刷新与持久化

- 数据写入：保留 64 KiB 读取缓冲区，每次 `WriteAt` 后在同一把状态锁内更新分块 `Written` 和总下载量。字节计数不经过通知通道，界面忙碌不会丢计数或阻塞上报。恢复时按分块偏移重新汇总总量，修正旧 JSON 中滞后的总计数。
- 界面与控制台：后台约每 200ms 发布刷新通知，状态变化立即通知；界面最多保留一个排队的刷新回调，执行时读取最新快照。速度按时间窗口采样，停滞时也能更新到零，不把续传前的字节算进本次速度。
- 状态保存：独立协程约每 1 秒检查一次，仅有新变化时保存，不再按新增字节数提前触发。开始、暂停、失败和完成时强制保存，取消时持久化取消意图并在后台结束后删除记录。
- 保存顺序：先串行化保存操作，再在短暂状态锁内复制包含分块和哈希映射的一致快照。JSON 编码、临时文件写入和原子替换在状态锁外执行；旧保存不能覆盖更新的最终状态。周期保存失败会停止当前下载并报告原因。

保存间隔意味着异常退出时，最近约一秒的进度可能尚未写入 JSON，恢复后会重下载这些字节；系统断电时的物理持久性仍取决于操作系统和磁盘缓存，本机制不保证断电后零进度损失。

## 文件名与同名任务

文件名优先从 `Content-Disposition` 响应头解析，支持普通 `filename` 和 UTF-8 编码的 `filename*`，包括中文、引号内的分号和转义字符。两者同时存在时优先使用 `filename*`。无有效文件名时回退到 URL 路径，最后才使用自动生成的名称。解析后仍会清理不安全的路径字符和 Windows 保留名称；不会额外解码字面量 `+` 或重复解码百分号。

新任务遇到已有文件时，依次尝试 `setup (1).exe`、`setup (2).exe` 等名称，不覆盖已有文件。通过排他创建文件来预留名称，避免并发任务同时选中同一个名字。选定的名称写入 JSON，暂停、重启后续传仍使用该名称，不重新编号。

同一进程内，不同下载器不能同时占用同一份 URL 状态记录或同一目标文件，冲突时返回 `ErrDownloadInUse`。界面重复添加同一链接时会继续已有的暂停/错误任务，或提示已有任务。此保护不等同于跨进程的续传锁。

运行下载核心的回归测试及竞态检测：

```powershell
go test -race ./internal/downloader
go vet ./internal/downloader
```
